---
title: Deploys
description: GitHub Actions deploy runs for the repos your panes are in, stacked above the bottom panel.
---

The Deploys section is a compact panel between the agent list and the bottom panel. It lists GitHub Actions runs that are deploying right now, plus the ones that finished recently — so a deploy that just went red is still on screen when you look up.

```
╭ Deploys 1 live ──────────────────────╮
│● sales-orders master              1m │
│✕ listing r2026.08.17.01          18m │
╰──────────────────────────────────────╯
```

Each row is one run: a status icon, the repo, the tag or branch it was dispatched from, and how long it has been going (or how long it took). Active runs sort first, then the most recently finished.

| Icon | Meaning                          |
| ---- | -------------------------------- |
| `●`  | running (the icon pulses)        |
| `◌`  | queued                           |
| `✓`  | finished successfully            |
| `✕`  | failed                           |
| `⊘`  | cancelled, skipped, or neutral   |

## Which runs show up

The sidebar collects the git repo root behind every pane it is tracking, turns each into an `owner/name` slug from its `origin` remote, and polls `gh run list` for it every 30 seconds. A run is a deploy when its workflow name contains `deploy`, case-insensitively — so `deploy`, `deploy-mcp`, and `etp-databases-deploy` all count.

This needs the [GitHub CLI](https://cli.github.com/) (`gh`) installed and authenticated. Without it the section simply stays empty; nothing else in the sidebar is affected.

The panel collapses to zero height whenever there is nothing to show, so the agent list keeps the whole sidebar on a quiet day.

## Options

| Option                        | Default  | Description                                                        |
| ----------------------------- | -------- | ------------------------------------------------------------------ |
| `@sidebar_deploys`            | `on`     | Set `off` to hide the section entirely                             |
| `@sidebar_deploy_match`       | `deploy` | Substring a workflow name must contain, case-insensitive           |
| `@sidebar_deploy_recent_mins` | `60`     | Minutes a finished deploy stays listed after it ends               |
| `@sidebar_deploy_max`         | `5`      | Maximum rows shown at once                                         |

For example, to track release workflows instead and keep them for two hours:

```tmux
set -g @sidebar_deploy_match release
set -g @sidebar_deploy_recent_mins 120
```
